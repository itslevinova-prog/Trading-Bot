# Clock-based costed barrier learning

The dataset and model are separate from previous gross endpoint targets and selected-policy PnL. The purpose is to learn an explicitly defined costed stop/target/horizon outcome at fixed, feature-eligible decision clocks, without conditioning the dataset on the old strategy having traded.

The registered corpus uses the same20survivor symbols, six already-consumed months Oct2025..Mar2026, exact raw-data union, two12h clocks daily,15m delayed-open entry, and32bars/8h horizon. A single common stop2%/target4% and fee0.1%/spread10bps/slippage8bps are bound to the target hash. These values reuse existing bounds; they were not optimized and are not recommended settings. The original8features retain ATR percentage and therefore volatility scale relative to these fixed distances. No variable per-trade target mixing or new predictor search.

All7280feature-eligible complete-path rows/364clocks were retained, including one ambiguous path with null payoff and57entry-bar events. Counterfactual open entry is an idealization; the57cases carry unresolved timing relative to a real delayed intra-candle decision. Do not delete them based on outcomes or claim exact executable fills.20assets at a clock are dependent. No independent sample count is known.

These differences explain why endpoint regression cannot silently stand in for a stop/target decision target. Counts are descriptive, not future probabilities or a portfolio return. All raw paths/costs and feature identities were independently verified. Full unresolved candles are saved in barrier-clock-corpus-verification.json.

The new research/barrier-learning.ts reuses the existing local ridge optimizer, but binds model snapshots to this costed target and feature schema. It verifies maturity of ALL rows (including ambiguous), target/cost/geometry/event consistency and duplicate/feature constraints. Only known labels train the model; ambiguous labels remain explicitly counted, never zero-filled. Actual fee-inclusive entry basis and raw exit reference are preserved in the optimizer adapter; y is already costed net return. The generic optimizer consumes x/y/clocks, not an assumed gross-price identity.
