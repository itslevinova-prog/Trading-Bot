# Entry risk input contract

The shared `validateRisk` is used by the existing Paper broker and historical replay. Before this correction it accepted several malformed inputs: negative/fractional trade counts, negative/fractional decision clocks, a NaN last-sale timestamp, duplicate held pair entries, position/risk fractions above one, fractional count limits, negative cooldown and invalid fee rates when portfolio stop budgeting was absent. Fourteen new regression cases first failed against the old code. These are malformed-state robustness defects; no claim is made that normal persisted accounts exhibited them.

The buy boundary now checks nonnegative safe integer clocks/counts, optional sale time no later than the decision, unique valued position pairs, percentage fractions in [0,1], nonnegative cooldown and fee in [0,1). Invalid buy input denies entry. Zero daily-entry limit continues to disable buys, zero cooldown remains valid, and the existing immediate sell authorization remains ahead of all entry validation. Invalid stop estimates still consume the prior conservative position-value fallback; no new entry or exit strategy is introduced.

A duplicate-position witness demonstrates the issue: two BTC entries valued at 10 each with equity 100 and 30% cap previously gave another 20 purchase budget, because only the first entry was subtracted. That would imply 40 total exposure against a cap of 30. The new boundary rejects ambiguous duplicated positions rather than guessing which valuation is authoritative. The normal database has unique pair constraints; this regression protects the shared function/replay boundary as well.

Validation: 19 new risk test cases (27 risk tests total), server/test typechecks, **122 test files / 1,622 tests passed**, plus 5,000 deterministic valid-state differential cases against archived main build `3b92fac27a6e17577dfdf400e0c75f44d62a870b9d106514b3cbf0405c086792`: zero changed valid outputs. Five explicit malformed-input witnesses now deny buys and still authorize sells. These are synthetic contract checks, not independent trading trials or profitability evidence. The full existing suite includes mocked legacy native/live contracts; no real order/provider was invoked.
