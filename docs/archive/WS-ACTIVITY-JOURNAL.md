[Official primary WebSocket specification](https://raw.githubusercontent.com/binance/binance-spot-api-docs/master/web-socket-streams.md) was read and snapshotted03November. The UTC combined kline stream supplies a finality flag, bar/event timestamps, OHLC/base volume, quote volume, trade count and taker-buy base/quote totals. The existing market-data-only host already subscribes to15minute kline messages. Full snapshot/hash/capture metadata are in docs/protocol-sources/binance-ws-streams-2026-11-03.*. This is a protocol reference, not new framework code or a new market-data request.

The parser requires exact stream/outer/inner symbol and15minutefinality/grid binding. Decimal strings are retained in original payload text and normalized exactly for semantic bar facts; OHLC/taker-total comparisons use decimal-integer arithmetic before floating conversion. Unsupported/nonfinite/unrepresentable/missing values do not become neutral zero. Measured zero volume retains unknown division shares. A raw-text hash and separate semantic bar-facts hash distinguish equivalent decimal formatting/event notifications from conflicting activity values.

Local receivedAt is separate from exchange eventAt and the bar's closedAt. Up to2seconds of ahead-of-local finality are bounded consistently with the existing candle buffer; availability waits until max(localreceipt,localclose,eventclock). Large future times fail closed. Late receipt is never backdated to bar close. These are conservative local-clock rules, not measured clock synchronization or proof of global first availability. Parser arguments/declaredsourceURL alone cannot authenticate actual transport: the trusted producer must bind a real main capture session/run before any decision consumer treats this as actual-source evidence.

WsActivityJournal imports no default application database/accounts and is intended for a DEDICATED public-capture database. Its writer appends accepted observations; exact repeats are idempotent, equivalent later notifications preserve earliest receipt, and global receipt regression is rejected rather than introducing backdated observations. Indexed receipt/market clocks avoid repeatedly scanning payloads. Reader initialization can be disabled for true read-only reopening. Raw hash/facts/id/clock integrity is recomputed on reads. Digests detect inconsistent local changes, not malicious rewriting of every hash or cryptographic exchange authentication.

As-of reads consider only observations actually received by that time. Later conflicting values invalidate the bar only from their observed receipt, without contaminating an earlier decision. Bounded future eligibility remains unavailable until its clock. Missing bars are unknown. Records are not silently replaced by late corrections. No REST-shaped12fieldrows are fabricated from WSdata or represented as previously observed history.

BinanceMarket adds an OPTIONAL fourth-argument observer for native final15minute payload text plus local arrival clock. Existing subscriptions, public requests, strategies and entry/exit paths are unchanged. Observer/storage errors are caught and normal candle handling continues. The default server constructor does NOT wire this observer, so there is no production capture table/file or running-process deployment in this phase.
