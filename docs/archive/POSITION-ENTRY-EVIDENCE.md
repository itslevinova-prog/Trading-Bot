# Recorded entry evidence for Paper positions

The working Paper broker now links each simulated buy to its concrete position ID and fill ID in the existing cash/trade/position transaction. No timestamp-nearest origin inference is used. A new append-only-by-application table position_entry_evidence references the buy trade (cascade on explicit trade deletion); it deliberately does not reference the live position because evidence must survive a full close.

At commit, the helper reads the currently durable owned decision in validated status and its original source context/actions and provider evidence. It checks source timestamps against the fill, a unique matching proposed buy, account/paper mode, original feature/market consistency, source closed structure and original book freshness. It copies a compact assessment/feature/structure rather than recursively duplicating full contexts. Full original source context/evidence byte hashes retain traceability. Raw provider text is not reinterpreted as a structured trading thesis. Actual applied stop/target prices and policy fingerprint are taken from the broker calculations, not inferred from later position values. Source policy and execution identity are retained, and historical-simulation origin remains distinguished from runtime Paper observations.

Missing decisions (including a manually issued order or the existing hold initializer whose decision is stored after its first fill), absent structured evidence, unknown scopes or old legacy positions stay explicitly unknown. This does not reject valid protective exits. Persistence failure rolls back the buy transaction, fake cash and holding together. Later updates to the source decision cannot replace the captured snapshot through the application; raw database editing is not prevented by a hash.

Scheduler context includes entryEvidence for each held position. Reading checks hash, ownership, position/fill identity, first capture availability, opening clock and quantity coverage. A partial sale retains the known opening evidence. A different reentry ID cannot inherit it. Scale-ins remain compound and are not automatically eligible for one whole-position thesis. An otherwise internally consistent opening snapshot also needs the current evaluation version to match before its eligibility marker is true; metadata is still no order permission or performance/calibration evidence.

Original support in the snapshot is a recorded contextual fact. It is not a retrospectively invented assertion that the original strategy explicitly used that exact level as its exit thesis. A proposed exit based on that level needs a separately stated strategy hypothesis and fair validation. No new exit/entry strategy is enabled by this change.

Validation: dedicated causal SQLite tests cover original evidence, later source mutation, wrong owner/action, duplicate actions/assessments, future/stale/mixed source data, configuration scope changes, legacy/compound entries, partial sales, reentries, corrupt snapshots, first-observation clocks and rollback. Actual PaperExecutionAdapter tests check concrete position/fill association, applied stop/target values, evidence retention after close and all-or-nothing rollback under an injected SQLite failure. The frozen prospective V3 and its database/source copy are not upgraded. This working-tree implementation is not represented as already deployed to that experiment.
