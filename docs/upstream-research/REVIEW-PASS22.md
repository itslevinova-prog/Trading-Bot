The adapter constructs a tree regressor from configured training parameters, uses train features/labels/weights, optionally supplies the datakitchen test split as eval_set/eval weights, and can obtain an initial per-pair model. That does not itself prove chronological purging, calibration or profit; the separately reviewed BaseRegressionModel fits feature/label transformations on the train partition and transforms the other partition. We keep strict explicit chronological maturity and cold independent fits rather than importing warm-start/framework state.

Selective implementation is an original offline bridge to the free BSD scikit-learn1.7.2 GradientBoostingRegressor. It uses a single fixed shallow-tree setting,8unchanged predictors and the existing costed target; no new economic results yet. scikit-learn/joblib/threadpoolctl were installed only in ignored project data/research-python-venv, with existing NumPy/SciPy reused read-only. Actual versions, RECORD hashes and complete notices are retained in docs/local-tree-environment.json and local-tree-libraries/. Core app has no Python dependency and no model-provider integration.

The public GradientBoostingRegressor documentation describes public estimators_/tree attributes and float32 conversion during prediction. The bridge exports numeric JSON, never pickle or executable model code, and the own TypeScript inference validates target hash, topology/depth/index/resource bounds, version/parameters, train-only scale, freshness and outliers. Float32 boundary parity is explicitly tested.46synthetic native sklearn predictions match portable inference;12TypeScript and6Python tests cover chronology, target mixing, unknown labels, hostile tree graphs and query data not altering fits. A predeclared tree is not automatically more useful than ridge; historical, ranking and broker evaluation remain required.
